📋 API 文档

跨平台崩溃上报服务 · 通用 REST API · v1 · Base URL http://localhost:8080/api/v1

0. 认证与权限

默认 API_REQUIRE_KEY=true。以下写入端点接受 Authorization: Bearer <api-key> 或 X-API-Key: <api-key>：崩溃上报、玩家反馈、Unity 上报、项目源码上传。viewer Key 不能写入。

curl -H "Authorization: Bearer <api-key>" ...
# 或
curl -H "X-API-Key: <api-key>" ...

查询、下载、分析、符号和管理 API 需要登录的 Session Cookie。修改类请求还必须携带 csrf_token Cookie 和对应的 X-CSRF-Token 请求头。admin/operator 可以查看崩溃详情；viewer 只能访问允许的只读列表页面；删除符号、删除反馈、清空崩溃仅限 admin。

# 登录并保存 auth_token 与 csrf_token Cookie
curl -c cookies.txt -H "Content-Type: application/json" \
  -d '{"username":"admin","password":"..."}' \
  http://localhost:8080/api/v1/auth/login

# 获取或刷新 CSRF token
curl -b cookies.txt -c cookies.txt http://localhost:8080/api/v1/auth/csrf

POST /api/v1/crash-report

提交崩溃报告。支持 JSON 与 multipart/form-data 两种格式。multipart 可以直接使用普通表单字段，或将完整 JSON 放入 report 字段；附件字段名为 attachments，最多 10 个。默认需要 operator/admin API Key。

📋 SDK 示例（C# 与 Python）

使用 HttpClient 的函数式封装——异步上报崩溃并返回 { id, group_id, is_new_group }。

using System;
using System.IO;
using System.Net.Http;
using System.Text;
using System.Text.Json;
using System.Text.Json.Serialization;
using System.Threading.Tasks;

public static class CrashReporter
{
    private static readonly HttpClient Http = new()
    {
        BaseAddress = new Uri("http://localhost:8080/api/v1")
    };

    /// <summary>以 JSON 上报崩溃，返回 { id, group_id, is_new_group }。</summary>
    public static async Task<CrashResult> ReportCrashAsync(
        string apiKey,
        string exceptionType,
        string projectName = null,
        string exceptionMessage = null,
        string stackTrace = null,
        string runtime = null,
        string runtimeVersion = null,
        string release = null,
        string platform = null,
        string appVersion = null,
        object customData = null)
    {
        var payload = new
        {
            exception_type = exceptionType,
            project_name = projectName,
            exception_message = exceptionMessage,
            stack_trace = stackTrace,
            runtime,
            runtime_version = runtimeVersion,
            release,
            platform,
            app_version = appVersion,
            custom_data = customData
        };

        using var request = new HttpRequestMessage(HttpMethod.Post, "crash-report")
        {
            Content = new StringContent(
                JsonSerializer.Serialize(payload), Encoding.UTF8, "application/json")
        };
        request.Headers.Add("X-API-Key", apiKey);

        using var response = await Http.SendAsync(request);
        response.EnsureSuccessStatusCode();
        return JsonSerializer.Deserialize<CrashResult>(
            await response.Content.ReadAsStringAsync());
    }

    /// <summary>以 multipart 附件上报崩溃（例如 dump 文件）。</summary>
    public static async Task<CrashResult> ReportCrashWithAttachmentAsync(
        string apiKey, string exceptionType, string stackTrace, string attachmentPath)
    {
        using var form = new MultipartFormDataContent
        {
            { new StringContent(exceptionType), "exception_type" },
            { new StringContent(stackTrace), "stack_trace" }
        };
        var fileBytes = await File.ReadAllBytesAsync(attachmentPath);
        form.Add(new ByteArrayContent(fileBytes), "attachments", Path.GetFileName(attachmentPath));

        using var request = new HttpRequestMessage(HttpMethod.Post, "crash-report")
        { Content = form };
        request.Headers.Add("X-API-Key", apiKey);

        using var response = await Http.SendAsync(request);
        response.EnsureSuccessStatusCode();
        return JsonSerializer.Deserialize<CrashResult>(
            await response.Content.ReadAsStringAsync());
    }
}

public sealed record CrashResult(
    [property: JsonPropertyName("id")] long Id,
    [property: JsonPropertyName("group_id")] long GroupId,
    [property: JsonPropertyName("is_new_group")] bool IsNewGroup);

用法：var result = await CrashReporter.ReportCrashAsync(key, "NullReferenceException", stackTrace: "...", runtime: "unity");

使用 requests 的函数式封装——返回服务器响应字典 { "id", "group_id", "is_new_group" }。

import requests
from typing import Any, Optional

API_BASE = "http://localhost:8080/api/v1"


def report_crash(
    exception_type: str,
    project_name: Optional[str] = None,
    exception_message: Optional[str] = None,
    stack_trace: Optional[str] = None,
    runtime: Optional[str] = None,
    runtime_version: Optional[str] = None,
    release: Optional[str] = None,
    platform: Optional[str] = None,
    app_version: Optional[str] = None,
    custom_data: Optional[dict] = None,
    attachments: Optional[list[str]] = None,
    api_key: str = "",
    api_base: str = API_BASE,
) -> dict[str, Any]:
    """上报崩溃并返回 {id, group_id, is_new_group}。

    在 `attachments` 中传入文件路径列表可将其作为 multipart
    文件上传（如 dump、日志文件，最多 10 个附件）。
    """
    headers = {"X-API-Key": api_key} if api_key else {}
    payload = {
        "exception_type": exception_type,
        "project_name": project_name,
        "exception_message": exception_message,
        "stack_trace": stack_trace,
        "runtime": runtime,
        "runtime_version": runtime_version,
        "release": release,
        "platform": platform,
        "app_version": app_version,
        "custom_data": custom_data,
    }
    payload = {k: v for k, v in payload.items() if v is not None}

    if attachments:
        files = [("attachments", (path, open(path, "rb"))) for path in attachments]
        try:
            resp = requests.post(
                f"{api_base}/crash-report", headers=headers, data=payload, files=files
            )
        finally:
            for _, handle in files:
                handle[1].close()
    else:
        resp = requests.post(f"{api_base}/crash-report", headers=headers, json=payload)

    resp.raise_for_status()
    return resp.json()

用法：result = report_crash("ValueError", stack_trace=traceback.format_exc(), runtime="python")

Node.js（Express）崩溃

curl -X POST http://localhost:8080/api/v1/crash-report \
  -H "X-API-Key: <key>" \
  -H "Content-Type: application/json" \
  -d '{
    "project_name": "api-gateway",
    "exception_type": "TypeError",
    "exception_message": "Cannot read properties of undefined (reading 'id')",
    "stack_trace": "at UserController.getUser (/app/controllers/user.js:42:15)\n    at Layer.handle (/app/node_modules/express/lib/router/layer.js:95:5)",
    "runtime": "node",
    "runtime_version": "20.11.0",
    "framework": "express",
    "environment": "production",
    "server_name": "api-gateway",
    "release": "abc1234",
    "app_version": "1.5.2"
  }'

multipart 上传（带 dump 附件）

curl -X POST http://localhost:8080/api/v1/crash-report \
  -H "X-API-Key: <key>" \
  -F "exception_type=NullReferenceException" \
  -F "stack_trace=at PlayerController.Update () [0x00000] in ..." \
  -F "runtime=unity" \
  -F "runtime_version=2022.3.10f1" \
  -F "attachments=@crash.dmp"

📤 响应（201 Created）

{
  "id": 42,
  "group_id": 7,
  "is_new_group": false
}

分组 hash：SHA256(exception_type | stack_trace | runtime [| project_name])[0:16]。完整堆栈（trim 后，缺失时为 no-stack）参与 hash——堆栈完全一致的崩溃归为一组。提供项目名时项目名也参与，不同项目不会混组。

POST/api/v1/project-sources

上传项目源码快照，供 Crash Analysis 定位崩溃代码行、函数定义和可能的调用位置。源码只作为文本检索——从不执行或编译。

multipart 字段：project_name 必填（1–100 字符）；release 可选（最大 200 字符）；通过重复的 files 字段提交单个文件，或通过 archive 上传 .tar.gz/.tgz 项目包——两者可以同时使用。内容与最新存储版本完全一致的文件会跳过（deduplicated）；小改动存为补丁（accepted[].storage = "patch"）；全部文件都被去重时不创建快照，snapshot_id 为 null。

分析时，源码匹配总是读取项目的「当前状态」——每个路径跨快照的最新版本——因此变更文件按新内容匹配、未变文件保持可用、新增文件立即生效。返回的 match_type 仍描述匹配到的快照（release 精确匹配为 exact，否则 latest）。按容器 Tier 限制：T1 10 文件/2 MB，T2 500 文件/200 MB，T3 50000 文件/5 GB，T4/T5 无 Tier 限制；单个源码文件最大 2 MiB。

curl -X POST http://localhost:8080/api/v1/project-sources \
  -H "X-API-Key: <key>" \
  -F "project_name=api-gateway" \
  -F "release=abc1234" \
  -F "archive=@api-gateway.tar.gz"

# 也可以上传多个单个源码文件
curl -X POST http://localhost:8080/api/v1/project-sources \
  -H "X-API-Key: <key>" \
  -F "project_name=api-gateway" \
  -F "release=abc1234" \
  -F "files=@src/app.ts;filename=src/app.ts" \
  -F "files=@src/service.ts;filename=src/service.ts"

响应（201）

{
  "project": { "id": 3, "name": "api-gateway" },
  "release": "abc1234",
  "snapshot_id": 9,
  "accepted": [
    { "path": "src/app.ts", "file_size": 2048, "language": "typescript", "storage": "full" },
    { "path": "src/config.ts", "file_size": 96, "language": "typescript", "storage": "patch" }
  ],
  "deduplicated": ["src/unchanged.ts"],
  "skipped": [{ "path": "assets/logo.png", "reason": "binary content" }]
}

任意文本文件均可上传（不限扩展名；同样支持非 Unity 项目）；拒绝绝对路径、.. 路径、二进制文件、超大文件及超限解包内容。

POST /api/v1/source-dedup

对已存储的源码行执行去重扫荡。服务器启动时自动执行一次，也可手动调用（仅 admin）。

  • 回填旧数据的内容哈希（hashes_backfilled）
  • 删除 (项目, 路径, 内容) 完全重复的行，保留最新——删除前先物化依赖它的补丁行
  • 清理孤儿磁盘文件（disk_files_removed, orphans_removed）
curl -X POST http://localhost:8080/api/v1/source-dedup \
  -b cookies.txt \
  -H "X-CSRF-Token: <token>"

响应

{
  "success": true,
  "hashes_backfilled": 12,
  "duplicates_removed": 3,
  "disk_files_removed": 2,
  "orphans_removed": 1
}

POST /api/v1/player-feedback

提交玩家发起的 bug 报告、建议或其他反馈。该端点与自动崩溃上报分开存储，不参与崩溃分组。支持 JSON，或 multipart/form-data 上传截图和日志附件。

📥 请求字段

字段类型说明
title *必填string反馈标题，最大 200 字符
description *必填string玩家描述的复现步骤、预期结果和实际结果
categorystringbug（默认）、suggestion 或 other
severitystringlow, normal（默认）, high, critical
player_id / player_name / contactstring可选的玩家 ID、显示名和联系方式
app_version / platform / device_model / scene_namestring版本与设备上下文，理想情况下由 Unity 自动填充
client_timestampstring玩家提交时间（ISO 8601）
custom_dataobject | string任意额外 JSON 数据

📋 JSON 示例

curl -X POST http://localhost:8080/api/v1/player-feedback \

POST /api/v1/unity/crash-report

Unity 专属崩溃上报端点。自动填充 runtime="unity" 和 framework="unity"，并将 unity_version 映射为 runtime_version。

参数与通用端点完全一致。额外行为：

  • 自动设置 runtime = "unity"
  • 自动设置 framework = "unity"
  • 未提供 runtime_version 时，自动使用 unity_version 的值
  • 支持 Unity IL2CPP 堆栈格式的 hash 分组

请求头必须包含 Unity User-Agent，或 X-Client-Type: unity。

示例

curl -X POST http://localhost:8080/api/v1/unity/crash-report \
  -H "X-API-Key: <key>" \
  -H "X-Client-Type: unity" \
  -H "Content-Type: application/json" \
  -d '{
    "exception_type": "NullReferenceException",
    "exception_message": "Object reference not set to an instance of an object",
    "stack_trace": "at PlayerController.Update () [0x00000] in /Assets/Scripts/PlayerController.cs:42",
    "unity_version": "2022.3.10f1",
    "platform": "Android",
    "device_model": "Samsung Galaxy S24",
    "os_version": "Android 14",
    "scene_name": "Level_01",
    "app_version": "1.2.3",
    "bundle_id": "com.example.mygame"
  }'

📤 响应（201 Created）

{
  "id": 43,
  "group_id": 8,
  "is_new_group": true,
  "runtime": "unity"
}

AI 12. AI 崩溃助手

面向 session 登录的 admin/operator 用户的智能崩溃分析助手。每个用户在 Accounts 页面配置自己的 DeepSeek API Key；Key 永不返回给浏览器，服务端使用 AI_ENCRYPTION_KEY 加密保存。

助手只读取当前用户有权访问的崩溃、确定性分析以及通过 API 上传的源码快照；没有源码时仅基于崩溃信息推断。

🤖 Agent 工具

工具说明安全边界
read_source_file读取已上传的项目源码（路径 / 行号范围 / 列表）仅限 DB 中的 relative_path——不接受文件系统路径
web_fetch抓取公开网页（官方文档 / 规范）SSRF 防护：连接时校验 IP；拦截私网/环回/链路本地/元数据地址；限制跳数和响应体积
run_bash在每会话独立工作目录复现问题默认关闭（AI_BASH_ENABLED=true 开启）；30s 超时、输出上限、最小环境变量、无网络隔离
update_tasks维护自身任务列表任务列表加密持久化，跨轮次可见
list_crashes列出用户有权访问的整个崩溃库（可选 search/status/limit 过滤），用于查找崩溃 id按容器作用域查询；仅返回摘要字段
update_crash_status修改崩溃状态（open/resolved/ignored，可选 resolved_version）；不带 group_id 时作用于会话绑定崩溃，带 group_id 时作用于指定崩溃group_id 写入前按容器作用域复核；子 Agent 不可用
spawn_subagent派子 Agent 调查子问题每轮最多 4 个、无嵌套、无 bash；步数计入总预算

循环步数上限：AI_MAX_TOOL_STEPS（默认 12）。Agent 循环会倍增 provider 调用次数，受每用户 AI_RATE_LIMIT（默认 20/分钟）约束。
