📋 API Documentation

Cross-platform crash reporting service · Generic REST API · v1 · Base URL http://localhost:8080/api/v1

0. Authentication & Permissions

Defaults to API_REQUIRE_KEY=true. The following write endpoints accept Authorization: Bearer <api-key> or X-API-Key: <api-key>: crash reporting, player feedback, Unity reporting, and project source upload. Viewer keys cannot write.

curl -H "Authorization: Bearer <api-key>" ...
# or
curl -H "X-API-Key: <api-key>" ...

Query, download, analysis, symbols, and management APIs require a logged-in session Cookie. Mutating requests must also carry the csrf_token Cookie and a matching X-CSRF-Token request header. admin/operator can view crash details; viewer can only access the allowed read-only list pages; deleting symbols, deleting feedback, and clearing crashes are admin-only.

# Log in and save the auth_token and csrf_token cookies
curl -c cookies.txt -H "Content-Type: application/json" \
  -d '{"username":"admin","password":"..."}' \
  http://localhost:8080/api/v1/auth/login

# Get or refresh the CSRF token
curl -b cookies.txt -c cookies.txt http://localhost:8080/api/v1/auth/csrf

POST /api/v1/crash-report

Submit a crash report. Supports both JSON and multipart/form-data. With multipart you can use plain form fields, or put the full JSON in the report field; attachments use the field name attachments, up to 10. Requires an operator/admin API key by default.

📋 SDK Examples (C# & Python)

Function-style wrapper using HttpClient — report a crash asynchronously and get back { id, group_id, is_new_group }.

using System;
using System.IO;
using System.Net.Http;
using System.Text;
using System.Text.Json;
using System.Text.Json.Serialization;
using System.Threading.Tasks;

public static class CrashReporter
{
    private static readonly HttpClient Http = new()
    {
        BaseAddress = new Uri("http://localhost:8080/api/v1")
    };

    /// <summary>Report a crash as JSON and return { id, group_id, is_new_group }.</summary>
    public static async Task<CrashResult> ReportCrashAsync(
        string apiKey,
        string exceptionType,
        string projectName = null,
        string exceptionMessage = null,
        string stackTrace = null,
        string runtime = null,
        string runtimeVersion = null,
        string release = null,
        string platform = null,
        string appVersion = null,
        object customData = null)
    {
        var payload = new
        {
            exception_type = exceptionType,
            project_name = projectName,
            exception_message = exceptionMessage,
            stack_trace = stackTrace,
            runtime,
            runtime_version = runtimeVersion,
            release,
            platform,
            app_version = appVersion,
            custom_data = customData
        };

        using var request = new HttpRequestMessage(HttpMethod.Post, "crash-report")
        {
            Content = new StringContent(
                JsonSerializer.Serialize(payload), Encoding.UTF8, "application/json")
        };
        request.Headers.Add("X-API-Key", apiKey);

        using var response = await Http.SendAsync(request);
        response.EnsureSuccessStatusCode();
        return JsonSerializer.Deserialize<CrashResult>(
            await response.Content.ReadAsStringAsync());
    }

    /// <summary>Report a crash with multipart attachment (e.g. a dump file).</summary>
    public static async Task<CrashResult> ReportCrashWithAttachmentAsync(
        string apiKey, string exceptionType, string stackTrace, string attachmentPath)
    {
        using var form = new MultipartFormDataContent
        {
            { new StringContent(exceptionType), "exception_type" },
            { new StringContent(stackTrace), "stack_trace" }
        };
        var fileBytes = await File.ReadAllBytesAsync(attachmentPath);
        form.Add(new ByteArrayContent(fileBytes), "attachments", Path.GetFileName(attachmentPath));

        using var request = new HttpRequestMessage(HttpMethod.Post, "crash-report")
        { Content = form };
        request.Headers.Add("X-API-Key", apiKey);

        using var response = await Http.SendAsync(request);
        response.EnsureSuccessStatusCode();
        return JsonSerializer.Deserialize<CrashResult>(
            await response.Content.ReadAsStringAsync());
    }
}

public sealed record CrashResult(
    [property: JsonPropertyName("id")] long Id,
    [property: JsonPropertyName("group_id")] long GroupId,
    [property: JsonPropertyName("is_new_group")] bool IsNewGroup);

Usage: var result = await CrashReporter.ReportCrashAsync(key, "NullReferenceException", stackTrace: "...", runtime: "unity");

Function-style wrapper using requests — returns the server response dict { "id", "group_id", "is_new_group" }.

import requests
from typing import Any, Optional

API_BASE = "http://localhost:8080/api/v1"


def report_crash(
    exception_type: str,
    project_name: Optional[str] = None,
    exception_message: Optional[str] = None,
    stack_trace: Optional[str] = None,
    runtime: Optional[str] = None,
    runtime_version: Optional[str] = None,
    release: Optional[str] = None,
    platform: Optional[str] = None,
    app_version: Optional[str] = None,
    custom_data: Optional[dict] = None,
    attachments: Optional[list[str]] = None,
    api_key: str = "",
    api_base: str = API_BASE,
) -> dict[str, Any]:
    """Report a crash and return {id, group_id, is_new_group}.

    Pass a list of file paths in `attachments` to upload them as
    multipart files (e.g. dump or log files, up to 10 attachments).
    """
    headers = {"X-API-Key": api_key} if api_key else {}
    payload = {
        "exception_type": exception_type,
        "project_name": project_name,
        "exception_message": exception_message,
        "stack_trace": stack_trace,
        "runtime": runtime,
        "runtime_version": runtime_version,
        "release": release,
        "platform": platform,
        "app_version": app_version,
        "custom_data": custom_data,
    }
    payload = {k: v for k, v in payload.items() if v is not None}

    if attachments:
        files = [("attachments", (path, open(path, "rb"))) for path in attachments]
        try:
            resp = requests.post(
                f"{api_base}/crash-report", headers=headers, data=payload, files=files
            )
        finally:
            for _, handle in files:
                handle[1].close()
    else:
        resp = requests.post(f"{api_base}/crash-report", headers=headers, json=payload)

    resp.raise_for_status()
    return resp.json()

Usage: result = report_crash("ValueError", stack_trace=traceback.format_exc(), runtime="python")

  -H "X-API-Key: <key>" \

  -F "stack_trace=at PlayerController.Update () [0x00000] in ..." \

📤 Response (201 Created)

{
  "id": 42,
  "group_id": 7,
  "is_new_group": false
}

Grouping hash: SHA256(exception_type | stack_trace | runtime [| project_name])[0:16]. The full stack trace (trimmed, or no-stack when missing) participates — identical crashes group together. When a project name is provided it also participates, so different projects never mix into the same group.

POST/api/v1/project-sources

Upload a project source snapshot, used by Crash Analysis to locate the crash line, function definitions, and possible call sites. Source code is only searched as text — it is never executed or compiled.

multipart fields: project_name required (1–100 characters); release optional (max 200 characters); submit individual files via repeated files fields, or upload a .tar.gz/.tgz project archive via archive — both can be used together. Files whose content is identical to the latest stored version are skipped (deduplicated); small changes are stored as patches (accepted[].storage = "patch"); when every file is skipped, no snapshot is created and snapshot_id is null.

During analysis, source matching always reads the project's current state — the latest version of each file across all snapshots — so changed files are matched by their new content, unchanged files stay available, and added files take effect immediately. The reported match_type still reflects the matched snapshot (exact when release matches, otherwise latest). Limits by container tier: T1 10 files/2 MB, T2 500 files/200 MB, T3 50000 files/5 GB, T4/T5 no tier limits; a single source file may be at most 2 MiB.

curl -X POST http://localhost:8080/api/v1/project-sources \
  -H "X-API-Key: <key>" \
  -F "project_name=api-gateway" \
  -F "release=abc1234" \
  -F "archive=@api-gateway.tar.gz"

# You can also upload multiple individual source files
curl -X POST http://localhost:8080/api/v1/project-sources \
  -H "X-API-Key: <key>" \
  -F "project_name=api-gateway" \
  -F "release=abc1234" \
  -F "files=@src/app.ts;filename=src/app.ts" \
  -F "files=@src/service.ts;filename=src/service.ts"

Response (201)

{
  "project": { "id": 3, "name": "api-gateway" },
  "release": "abc1234",
  "snapshot_id": 9,
  "accepted": [
    { "path": "src/app.ts", "file_size": 2048, "language": "typescript", "storage": "full" },
    { "path": "src/config.ts", "file_size": 96, "language": "typescript", "storage": "patch" }
  ],
  "deduplicated": ["src/unchanged.ts"],
  "skipped": [{ "path": "assets/logo.png", "reason": "binary content" }]
}

Any text file can be uploaded (any extension; non-Unity projects are supported too); absolute paths, .. paths, binary files, oversized files, and over-limit extracted contents are rejected.

POST /api/v1/source-dedup

Run a deduplication sweep over stored source rows. Runs automatically once at server startup; can also be invoked manually (admin only).

  • Backfills content hashes for legacy rows (hashes_backfilled)
  • Deletes fully duplicated (project, path, content) rows, keeping the newest — materializing dependent patch rows first
  • Cleans up orphaned disk files (disk_files_removed, orphans_removed)
curl -X POST http://localhost:8080/api/v1/source-dedup \
  -b cookies.txt \
  -H "X-CSRF-Token: <token>"

Response

{
  "success": true,
  "hashes_backfilled": 12,
  "duplicates_removed": 3,
  "disk_files_removed": 2,
  "orphans_removed": 1
}

POST /api/v1/unity/crash-report

Unity-specific crash reporting endpoint. Auto-fills runtime="unity" and framework="unity", and maps unity_version to runtime_version.

Accepts exactly the same parameters as the generic endpoint. Additional behavior:

  • Automatically sets runtime = "unity"
  • Automatically sets framework = "unity"
  • If runtime_version is not provided, the unity_version value is used automatically
  • Supports hash grouping of Unity IL2CPP stack formats

The request header must include a Unity User-Agent, or X-Client-Type: unity.

Example

curl -X POST http://localhost:8080/api/v1/unity/crash-report \
  -H "X-API-Key: <key>" \
  -H "X-Client-Type: unity" \
  -H "Content-Type: application/json" \
  -d '{
    "exception_type": "NullReferenceException",
    "exception_message": "Object reference not set to an instance of an object",
    "stack_trace": "at PlayerController.Update () [0x00000] in /Assets/Scripts/PlayerController.cs:42",
    "unity_version": "2022.3.10f1",
    "platform": "Android",
    "device_model": "Samsung Galaxy S24",
    "os_version": "Android 14",
    "scene_name": "Level_01",
    "app_version": "1.2.3",
    "bundle_id": "com.example.mygame"
  }'

📤 Response (201 Created)

{
  "id": 43,
  "group_id": 8,
  "is_new_group": true,
  "runtime": "unity"

GET/api/v1/crash-reports/:id/analysis

Returns structured Crash Analysis: language detection, file tree, trigger point, colorized stack chain, crash path flow, fix suggestions, and — after matching against a source snapshot — the actual crashing code, function definitions, related files, and root-cause candidates.

Source matching requires the report to include project_name and the project's sources to have been uploaded via /project-sources. A matching release is preferred; otherwise match_type=latest. Matching always reads the project's current state (latest row per path across snapshots).

🔬 Dump Parsing

The server has a built-in dump parsing module; uploaded attachments are auto-detected and parsed. Results are stored in the dump_info field.

Supported Dump Formats

Format Extension Parsed Content
Android Tombstone .txt, .tombstone Signal, fault address, backtrace, memory map, build fingerprint, abort message
iOS/macOS Crash .crash, .ips Exception type, signal, crashed thread, all thread backtraces, binary images, registers
Windows Minidump .dmp, .mdmp System info (OS/CPU), exception record, thread list, module list
Unity Log .log, .txt Exception lines, stack traces, crash context (surrounding lines), Fatal Error / signal markers

The parser auto-detects the format via file extension and content characteristics (heuristics). Upload any dump in the attachments field and it will be parsed automatically.

📦 Export / Import

`.crashpkg` is a tar.gz containing a manifest, report JSONs and attachment files. New packages carry the project name; old packages can still be imported.

GET /api/v1/export/group/:id

Export a crash group as .crashpkg (tar.gz), containing manifest.json, all report JSONs, and attachment files.

curl http://localhost:8080/api/v1/export/group/1 -o crash-group-1.crashpkg

POST /api/v1/import

Import a .crashpkg crash data package. Query: confirm=true performs the real write, confirm=false is a dry run (checks conflicts only). Supports multipart upload, raw binary, or base64 encoding.

# Dry run
curl -X POST "http://localhost:8080/api/v1/import?confirm=false" \
  -F "package=@crash-group-1.crashpkg"

# Real import
curl -X POST "http://localhost:8080/api/v1/import?confirm=true" \
  -F "package=@crash-group-1.crashpkg"

AI 12. AI Crash Assistant

An agentic crash-analysis assistant available to session-logged-in admin/operator users. Each user configures their own DeepSeek API key on the Accounts page; keys are never returned to the browser and are stored encrypted with AI_ENCRYPTION_KEY.

The assistant only reads crashes the current user is authorized to access, deterministic analyses, and source snapshots uploaded via the API. Without sources it infers from the crash information alone.

🤖 Agent Tools

ToolDescriptionSafety Boundary
read_source_fileRead uploaded project sources (path / line range / listing)DB relative_path only — no filesystem paths
web_fetchFetch public web pages (official docs / specs)SSRF guard: IP validated at connect time; private/loopback/link-local/metadata addresses blocked; redirect and response-size limits
run_bashReproduce issues in a per-conversation workspaceOff by default (AI_BASH_ENABLED=true); 30s timeout, output cap, minimal env, no network isolation
update_tasksMaintain its own task listTask list persisted encrypted, visible across turns
spawn_subagentDelegate focused sub-investigationsMax 4 per turn, no nesting, no bash; steps count toward the budget

Loop step limit: AI_MAX_TOOL_STEPS (default 12). The agent loop multiplies provider calls, bounded per-user by AI_RATE_LIMIT (default 20/min).
