Authentication & Permissions

Defaults to API_REQUIRE_KEY=true. The following write endpoints accept Authorization: Bearer <api-key> or X-API-Key: <api-key>: crash reporting, player feedback, Unity reporting, and project source upload. Viewer keys cannot write.

curl -H "Authorization: Bearer <api-key>" ...
# or
curl -H "X-API-Key: <api-key>" ...

Query, download, analysis, symbols, and management APIs require a logged-in session Cookie. Mutating requests must also carry the csrf_token Cookie and a matching X-CSRF-Token request header. admin/operator can view crash details; viewer can only access the allowed read-only list pages; deleting symbols, deleting feedback, and clearing crashes are admin-only.

# Log in and save the auth_token and csrf_token cookies
curl -c cookies.txt -H "Content-Type: application/json" \\
  -d '{"username":"admin","password":"..."}' \\
  http://localhost:8080/api/v1/auth/login

# Get or refresh the CSRF token
curl -b cookies.txt -c cookies.txt http://localhost:8080/api/v1/auth/csrf

Account APIs live under /api/v1/auth: /me, /users, /api-keys, user password change, admin password reset, forgot/reset password, and API key tier change.

POST /api/v1/crash-report

Submit a crash report. Supports both JSON and multipart/form-data. With multipart you can use plain form fields, or put the full JSON in the report field; attachments use the field name attachments, up to 10. Requires an operator/admin API key by default.

📥 Request Body Parameters (JSON)

server_namestringService name / application identifier

📋 Example Request

Node.js (Express) crash

curl -X POST http://localhost:8080/api/v1/crash-report \\
  -H "X-API-Key: <key>" \\
  -H "Content-Type: application/json" \\
  -d '{
    "project_name": "api-gateway",
    "exception_type": "TypeError",
    "exception_message": "Cannot read properties of undefined (reading 'id')",
    "stack_trace": "at UserController.getUser (/app/controllers/user.js:42:15)\\n    at Layer.handle (/app/node_modules/express/lib/router/layer.js:95:5)",
    "runtime": "node",
    "runtime_version": "20.11.0",
    "framework": "express",
    "environment": "production",
    "server_name": "api-gateway",
    "release": "abc1234",
    "app_version": "1.5.2"
  }'

Python crash

curl -X POST http://localhost:8080/api/v1/crash-report \\
  -H "X-API-Key: <key>" \\
  -H "Content-Type: application/json" \\
  -d '{
    "exception_type": "ValueError",
    "exception_message": "invalid literal for int()",
    "stack_trace": "Traceback (most recent call last):\\n  File \"/app/main.py\", line 28, in process\\n    count = int(value)\\nValueError: invalid literal for int()",
    "runtime": "python",
    "runtime_version": "3.12.3",
    "framework": "fastapi",
    "environment": "production"
  }'

Multipart form upload (with dump attachment)

curl -X POST http://localhost:8080/api/v1/crash-report \\
  -H "X-API-Key: <key>" \\
  -F "exception_type=NullReferenceException" \\
  -F "stack_trace=at PlayerController.Update () [0x00000] in ..." \\
  -F "runtime=unity" \\
  -F "runtime_version=2022.3.10f1" \\
  -F "attachments=@crash.dmp"

📤 Response (201 Created)

{
  "id": 42,
  "group_id": 7,
  "is_new_group": false
}

When no project name is provided, the legacy grouping algorithm is used and the group shows as Unassigned; when a project name is provided, it also participates in the SHA-256 grouping hash, so different projects never mix into the same group.

POST/api/v1/project-sources

Upload a project source snapshot, used by Crash Analysis to locate the crash line, function definitions, and possible call sites. Source code is only searched as text — it is never executed or compiled.

multipart fields: project_name required (1–100 characters); release optional (max 200 characters); submit individual files via repeated files fields, or upload a .tar.gz/.tgz project archive via archive — both can be used together. A successful upload creates an immutable source snapshot.

During analysis, an exact match on project_name + release is tried first; if no matching release exists, it falls back to the project's latest snapshot. Limits by container tier: T1 10 files/2 MB, T2 500 files/200 MB, T3 50000 files/5 GB, T4/T5 no tier limits; a single source file may be at most 2 MiB.

curl -X POST http://localhost:8080/api/v1/project-sources \\
  -H "X-API-Key: <key>" \\
  -F "project_name=api-gateway" \\
  -F "release=abc1234" \\
  -F "archive=@api-gateway.tar.gz"

# You can also upload multiple individual source files
curl -X POST http://localhost:8080/api/v1/project-sources \\
  -H "X-API-Key: <key>" \\
  -F "project_name=api-gateway" \\
  -F "release=abc1234" \\
  -F "files=@src/app.ts;filename=src/app.ts" \\
  -F "files=@src/service.ts;filename=src/service.ts"

Response (201)

{
  "project": { "id": 3, "name": "api-gateway" },
  "release": "abc1234",
  "snapshot_id": 9,
  "accepted": [{ "path": "src/app.ts", "file_size": 2048, "language": "typescript" }],
  "skipped": [{ "path": "assets/logo.png", "reason": "binary content" }]
}

Any text file can be uploaded (any extension; non-Unity projects are supported too); absolute paths, .. paths, binary files, oversized files, and over-limit extracted contents are rejected.

POST /api/v1/player-feedback

Submit player-initiated bug reports, suggestions, or other feedback. This endpoint is stored separately from automatic crash reporting and does not participate in crash grouping. Supports JSON, or multipart/form-data for uploading screenshots and log attachments.

📥 Request Fields

FieldTypeDescription
title *requiredstringFeedback title, max 200 characters
description *requiredstringReproduction steps, expected results, and actual results described by the player
categorystringbug (default), suggestion, or other
severitystringlow, normal (default), high, or critical
player_id / player_name / contactstringOptional player ID, display name, and follow-up contact
app_version / platform / device_model / scene_namestringVersion and device context, ideally auto-filled by Unity
client_timestampstringISO 8601 timestamp of player submission
custom_dataobject | stringAny extra JSON data

📋 JSON Example

curl -X POST http://localhost:8080/api/v1/player-feedback \\
  -H "X-API-Key: <key>" \\
  -H "Content-Type: application/json" \\
  -d '{
    "title": "Cannot equip new weapon after purchase",
    "description": "After buying a weapon in the shop, clicking the equip button does nothing.",
    "category": "bug",
    "severity": "high",
    "player_id": "player-123",
    "app_version": "2.0.0",
    "platform": "Android",
    "device_model": "Samsung Galaxy S24",
    "scene_name": "Shop"
  }'

📎 Upload Screenshots or Logs

With multipart/form-data, put the full JSON in the feedback field; repeat the attachments file field for multiple files, up to 10 files, each limited by MAX_ATTACHMENT_SIZE.

curl -X POST http://localhost:8080/api/v1/player-feedback \\
  -H "X-API-Key: <key>" \\
  -F 'feedback={"title":"Quest stuck","description":"Cannot continue after finishing the dialogue","category":"bug"};type=application/json' \\
  -F "attachments=@screenshot.png" \\
  -F "attachments=@Player.log"

📤 Response (201 Created)

{
  "id": 12,
  "status": "new",
  "attachments": [{ "id": 8, "filename": "screenshot.png", "file_size": 243901 }]
}

GET/api/v1/player-feedback

Get the list of player feedback. This admin endpoint requires a logged-in session Cookie.

Query parameters: page (default 1), page_size (default 20, max 100), status (new, in_progress, resolved, closed), category, and search (title, description, or player name).

curl http://localhost:8080/api/v1/player-feedback?status=new&category=bug

GET/api/v1/player-feedback/:id

Get a single feedback entry with its attachment metadata (login required).

curl http://localhost:8080/api/v1/player-feedback/12

PUT/api/v1/player-feedback/:id/status

Update the feedback processing status (login required).

curl -X PUT http://localhost:8080/api/v1/player-feedback/12/status \\
  -H "Content-Type: application/json" \\
  -d '{"status":"in_progress"}'

Valid status values: new, in_progress, resolved, closed.

GET/api/v1/download/player-feedback/attachment/:id

Download a single attachment uploaded with player feedback (login required).

POST /api/v1/unity/crash-report

Unity-specific crash reporting endpoint. Auto-fills runtime="unity" and framework="unity", and maps unity_version to runtime_version.

Accepts exactly the same parameters as the generic endpoint. Additional behavior:

  • Automatically sets runtime = "unity"
  • Automatically sets framework = "unity"
  • If runtime_version is not provided, the unity_version value is used automatically
  • Supports hash grouping of Unity IL2CPP stack formats

Example

curl -X POST http://localhost:8080/api/v1/unity/crash-report \\
  -H "X-API-Key: <key>" \\
  -H "X-Client-Type: unity" \\
  -H "Content-Type: application/json" \\
  -d '{
    "exception_type": "NullReferenceException",
    "exception_message": "Object reference not set to an instance of an object",
    "stack_trace": "at PlayerController.Update () [0x00000] in /Assets/Scripts/PlayerController.cs:42",
    "unity_version": "2022.3.10f1",
    "platform": "Android",
    "device_model": "Samsung Galaxy S24",
    "os_version": "Android 14",
    "scene_name": "Level_01",
    "app_version": "1.2.3",
    "bundle_id": "com.example.mygame"
  }'

📤 Response (201 Created)

{
  "id": 43,
  "group_id": 8,
  "is_new_group": true,
  "runtime": "unity"
}

GET/api/v1/crash-reports/:id/analysis

Returns structured Crash Analysis: language detection, file tree, trigger point, colorized stack chain, and — after matching against a source snapshot — the actual crashing code, function definitions, and up to 20 possible reference locations.

Source matching requires the report to include project_name and the project's sources to have been uploaded via /project-sources. A matching release is preferred; otherwise match_type=latest.

{
  "detected_language": "typescript",
  "trigger_point": { "file_path": "src/service.ts", "line_number": 42, "function_name": "loadUser" },
  "source_analysis": {
    "project_name": "api-gateway",
    "requested_release": "abc1234",
    "snapshot_release": "abc1234",
    "match_type": "exact",
    "crash_source": { "file_path": "src/service.ts", "line_number": 42, "snippet": "..." },
    "function_definition": { "file_path": "src/service.ts", "line_number": 35, "snippet": "..." },
    "references": [],
    "warnings": []
  }
}

GET/api/v1/crash-reports/:id/symbolication

🔬 Dump Parsing

The server has a built-in dump parsing module; uploaded attachments are auto-detected and parsed. Results are stored in the dump_info field.

Supported Dump Formats

Format Extension Parsed Content
Android Tombstone .txt, .tombstone Signal, fault address, backtrace, memory map, build fingerprint, abort message
iOS/macOS Crash .crash, .ips Exception type, signal, crashed thread, all thread backtraces, binary images, registers
Windows Minidump .dmp, .mdmp System info (OS/CPU), exception record, thread list, module list
Unity Log .log, .txt Exception lines, stack traces, crash context (surrounding lines), Fatal Error / signal markers

The parser auto-detects the format via file extension and content characteristics (heuristics). Upload any dump in the attachments field and it will be parsed automatically.

📦 Export / Import

GET /api/v1/export/group/:id

Export a crash group as .crashpkg (tar.gz), containing manifest.json, all report JSONs, and attachment files.

curl http://localhost:8080/api/v1/export/group/1 -o crash-group-1.crashpkg

POST /api/v1/import

Import a .crashpkg crash data package. Query: confirm=true performs the real write, confirm=false is a dry run (checks conflicts only). Supports multipart upload, raw binary, or base64 encoding.

# Dry run
curl -X POST "http://localhost:8080/api/v1/import?confirm=false" \\
  -F "package=@crash-group-1.crashpkg"

# Real import
curl -X POST "http://localhost:8080/api/v1/import?confirm=true" \\
  -F "package=@crash-group-1.crashpkg"

Dry-run response

{
  "dry_run": true,
  "conflicts": [{ "crash_hash": "a8002ef4f65bcd40", "existing_group_id": 1 }],
  "new_groups": 0,
  "new_reports": 5,
  "new_attachments": 2
}

Real import response

{
  "dry_run": false,
  "conflicts": [],
  "new_groups": 1,
  "new_reports": 5,
  "new_attachments": 2,
  "group_id": 10
}
